## 战报、评分与数据口径

- 玩家概览、近期列表、单局战报共用展示数据和格式；精简重复说明，保留样本范围、未知值和旧缓存标识。
- 分值 K/D 使用摧毁分与损失分；击杀/阵亡是单位数量，伤害/承伤是另一组数据。出兵花费、补给消耗保留有效小数，不被整数格式误判为缺失。
- 分析接口只以明确布尔 `won` 及相同对局 ID 提供目标玩家胜负；不将 ELO 涨跌当成展示的权威胜负。单局页保留已知目标胜负。
- 分析样本与近期样本分别标明；重复和相互矛盾的分析结果不重复计入分母。地图、单位按来源 ID 关联。
- 「评分」移植固定 ba-dragon 模型的逐局 career 计算，按分数着色，不展示称号。保留 MIT 来源与完整许可。
- Oracle 包含原始 160 个样本，以及逐个删除 `StartTime` 的 160 个边界样本。开始/结束时间分别保留；不以结束时间减时长反推开始时间。近期列表按真实结束时间、缺少时按真实开始时间排序，两者都缺少才放最后。
- 赛前预测使用 A/B 队全部必要赛前 ELO；兵种构成按已收录单位基础价格估算。缺少成员单位数据或存在未知价格时，不把已识别部分重新归一化为完整构成。
- 队伍摘要的赛前平均 ELO 使用传递到展示层的赛前值；本局 `NewRating` 标明为赛后平均 ELO，不将历史对局的赛后值称为当前值。
- 单局图片按 900 CSS 像素渲染：顶部预测及 A/B 队伍摘要，中部左侧兵种构成、右侧双方对比，底部玩家。其他卡片为 390 CSS 像素；运行仍使用 JPEG 85、ultra 像素比。
- 双方对比与逐兵种构成都共用左 A、右 B 的横条；兵种使用对应类别的同色系深浅色（A 深、B 浅）。构成数值保持双方各自占比，横条按这两个占比划分；缺失值与 0/0 不生成虚假的比例。
- 所有图片页脚为本地内嵌 GitHub Logo、`timeance/astrbot_plugin_BA_stats` 和「数据来源 BATracer」。深浅主题分别使用官方白色与黑色 Logo，不在运行时请求素材。
- 图片默认浅色；原生配置、独立设置中心和渲染器默认值一致，已保存的深色选择保持有效。图片缓存摘要包含完整 HTML，样式、主题和 Logo 变更会生成新缓存。

## 设置中心与诊断

- 独立视图 `views/settings/`，与原生配置共用 AstrBotConfig；常用、额度、维护、诊断分组。跟随宿主深浅主题，维护和诊断内容默认折叠。
- 按 schema 描述与白名单校验字段，API origin 与客户端复用同一 HTTPS 校验规则；不返回或接受旧客户端标识、令牌、全局额度字段。
- 自定义设置中心保存检查磁盘配置版本，冲突返回 409 并保留页面草稿。普通设置等待手动重载，页面显示待生效项；诊断开关保存后即时应用，保存不重启业务对象或中断在途请求。AstrBot 原生插件设置保存时由宿主自动重载。
- API 使用 AstrBot 登录鉴权，插件额外检查用户名。未登录、已关闭、无效 JSON、非法类型/范围、保存失败及旧实例卸载有回归测试。下载不通过公开静态目录。
- 诊断仅记录允许的事件与字段：请求耗时/状态、渲染及图片发送阶段、文件类型/大小、受控错误分类等。日志上限为 `30 * 1024 * 1024` 字节，旧段自动淘汰；关闭后可下载既有日志。
- 记录器覆盖轮换、并发导出、关闭、磁盘失败及脱敏；不记录令牌、请求头、完整响应、聊天正文或图片内容。导出为 ZIP，不清空原日志。
- 本地浏览器验证保存开关、下载路由、409 草稿保留、重新读取后保留草稿、待重载提示及固定总额度；验证 Base64 默认值，以及 file/url 保存后等待重载。本轮增加图片浅色默认值、切换主题和保留已保存深色的检查。合成桥接不替代真实宿主收发；常用设置全页预览将悬浮保存栏放到文档末尾，交互测试使用原样 CSS。

## 图片发送与损坏缓存

用户环境为 AstrBot 4.29.4、NapCat.Core 4.18.18；其他插件能发图片。用户日志显示 OneBot `retcode=1200`、QQ `sendMsg` 确认超时。

用户提供的诊断 ZIP 显示，玩家概览和单局图片缓存仅有 20 字节，随后发送超时。没有取得该缓存文件原始正文，因此不能断言具体错误响应内容。固定版本 AstrBot 的远程渲染下载路径未验证响应状态和图片内容，插件原先也只检查文件是否存在。

v0.1.3 共用图片下载与验证流程：检查 HTTP 状态，限制下载大小与重定向，通过 Pillow 验证并完整解码图片。缓存命中也重新验证；当前摘要的损坏图片会删除并重新生成，新产生的无效文件不会进入缓存或发送。只处理图片缓存，保留查询缓存、绑定和额度记录。

- Base64 为默认方式，使用 AstrBot 标准图片组件并等待发送结果；本地文件和链接方式直接调用 OneBot，分别传入 file URI 和实际 HTTP(S) URL，群聊和私聊均保留当前机器人 self_id。
- 链接方式每次获取新地址。渲染器只返回本地路径或平台不支持对应方式时，明确报错，不伪造链接、不自动切换方式重发。
- 生成、下载、校验或发送失败均在控制台记录 ERROR，包含方式、阶段和受控原因；诊断关闭也不会隐藏这些错误。不记录原始异常正文、签名 URL、Base64 或凭据。
- 回归覆盖 20 字节无效文件、损坏及截断图片、旧缓存重建、错误响应不落盘、三种发送方式、群聊/私聊路由及不自动切换重发。文字回退复用同一次查询并关闭自动转图。

这些结果证明离线流程与坏缓存处理通过测试，**不代表已完成真实 QQ 收发验收**。仍需在用户实例安装后验证；不能将旧日志中的所有 QQ 超时都归因为相同原因。
